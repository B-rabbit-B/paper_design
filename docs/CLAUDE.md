# docs/：规划、验收材料与开题报告

先读根目录 `CLAUDE.md`。

| 路径 | 内容 | 能不能改 |
|---|---|---|
| `plan/总纲-分阶段实施与验收.md` | **总纲**：阶段 0–5 的任务、验收清单、验收记录 | 可以改，但验收标准的变更要经用户同意并在验收记录里引用原话 |
| `plan/00`–`03` | 总体方案、数据集、训练评估、系统改造的详细方案 | 可以改；与总纲冲突时以总纲为准（01 开头有更正说明） |
| `acceptance/stage-N/` | 各阶段的证据文件（文件名以验收项编号开头）和审查报告 | **事后不得修改**；审查报告不得改，要补充就新建 `-r2`、`-r3` |
| `acceptance/commit-hash-map.md` | 作者身份改写后新旧提交号对照 | 只增补，不改已有行 |
| `开题报告/` | 开题报告（.docx） | 只读；进度以它的毕设周次为准 |

## 约定

- 决策和验收写成文档，不要只留在对话里。
- 证据文件由命令产生并保存输出（`Tee-Object` 或 `tee`），不要手写"通过"。
- 文档里写数字前先用命令核实，数据集合并一次数字就会变；写的是估计就明说是估计。
- 在 Bash 工具的 heredoc 里用 Python 写带反斜杠的文档内容，转义会被提前处理（`\b` 会变成退格符），这类改动用 Edit 工具，写完用 `grep -c $'\x08' <文件>` 检查。
