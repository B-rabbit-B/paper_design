## 3. 推荐组合与理由

**主数据集**（合并后目标 25–35 类，1.5–2.5 万张）：
1. LVIS 果蔬子集（8,221 张，63 类，YOLO 格式）
2. Zenodo Multi-Class Fruit and Vegetable Detection（20,216 张，30 类，YOLO 格式）

两者取交集/并集类别，合并时统一英文类名（如 `capsicum` → `bell_pepper`），按 §1 表格的 33 类做筛选与合并，剔除框数过少（<50）的长尾类。

**补充数据集**：
3. Mendeley 孟加拉 22 类蔬菜检测集 —— 补充堆叠/菜摊场景，提升遮挡鲁棒性
4. Roboflow Vegetables（vegetables-el4g6）—— 只挑主集缺的蔬菜类，导出后做哈希去重
5. Open Images V7 —— 一次性用代理拉取 Egg (Food)、Meat、Chicken、Fish、Shrimp、Mushroom 等，每类 300–800 张，补齐蛋类/肉类/水产（前四个数据集里几乎没有这些类）
6. AIcrowd Food Recognition 2022（可选）—— 筛 `*-raw`/`egg` 等生食类作进一步补充

**自采数据**（论文加分核心）：
7. 手机拍摄 300–500 张国内冰箱、菜篓、案板场景照片，重点覆盖公开数据集里稀缺的中国家庭常见食材：白菜、青椒、葱姜蒜、豆腐、鸡蛋、五花肉、鸡腿、鱼、虾等。作为**独立测试集**评估域偏移（训练/验证不用它），再取一半做微调，能在论文里给出"公开数据集训练 → 真实国内场景测试 → 微调后提升"的完整对比，这是本课题区别于网上一堆"用 Kaggle 数据集训个 YOLO"的项目的关键说服力来源。

**明确不用**：Fruits-360（白底转台图，域差异过大）；UECFOOD/VireoFood/ISIA/Food2K/ChineseFoodNet/UNIMIB（菜品级或链接失效）；Freiburg Groceries（包装食品非生鲜）；来源不明的第三方打包数据集。

### 4.3 Roboflow Universe

网页注册（建议邮箱注册而非 Google 登录，减少代理依赖）→ 打开数据集页 → Download Dataset → 格式选 **YOLOv8** → 复制生成的下载代码或直接下载 zip 到 `training/datasets/raw/roboflow_<name>/`。免费版每月 15 credits，**数据集导出本身不消耗 credits**（消耗项是云端标注/训练/推理），够用。

### 4.4 Open Images V7（经代理，用 fiftyone 按类下载）

```bash
pip install fiftyone
python - <<'EOF'
import fiftyone as fo
import fiftyone.zoo as foz

classes = ["Egg (Food)", "Chicken", "Meat", "Fish", "Shrimp", "Mushroom",
           "Cabbage", "Carrot", "Tomato", "Potato"]
dataset = foz.load_zoo_dataset(
    "open-images-v7",
    split="train",
    label_types=["detections"],
    classes=classes,
    max_samples=800 * len(classes),
    seed=42,
)
dataset.export(
    export_dir="training/datasets/raw/openimages",
    dataset_type=fo.types.YOLOv5Dataset,
    classes=classes,
)
EOF
```

### 4.5 VOC → YOLO / COCO → YOLO 转换

Mendeley（VOC XML）和 AIcrowd（COCO JSON）都不是原生 YOLO 格式，用 ultralytics 自带转换器：

```python
from ultralytics.data.converter import convert_coco
convert_coco(labels_dir="training/datasets/raw/aicrowd/annotations", save_dir="training/datasets/raw/aicrowd_yolo", use_segments=False)
```

VOC XML 转 YOLO 没有官方一键工具，`training/sources/mendeley.py` 中自行实现约 20 行的 XML 解析（读 `<object><bndbox>` 的 xmin/ymin/xmax/ymax，除以图片宽高归一化）。

## 5. 自采数据规范

- **拍摄清单**：优先拍公开数据集稀缺的类别——蛋类、肉类（猪肉/牛肉/鸡肉）、水产（鱼/虾）、豆腐、葱姜蒜、白菜等中国家庭常见食材；每类不少于 15–20 张不同角度/光照/组合的照片。
- **拍摄场景**：冰箱各层（冷藏格、抽屉）、菜篓/菜篮、厨房案板、超市塑料袋装。
- **多样性要求**：不同光照（自然光/冰箱灯/顶灯）、不同角度（俯拍/斜拍）、不同遮挡程度（单个摆放 + 多个堆叠）、不同背景。
- **标注工具**：labelImg（轻量，Windows 下 `pip install labelImg` 直接跑）或 X-AnyLabeling（支持辅助标注加速），标注框选可见边界，遮挡超过 70% 的个体不标注，同类别多个实例分别标注独立的框。
- **导出格式**：直接导出 YOLO txt 格式（`cls cx cy w h` 归一化坐标），放入 `training/datasets/raw/custom/images` 与 `labels`。
- **EXIF 处理**：手机照片可能带旋转 EXIF 信息，`training/prepare_dataset.py` 的自采源适配器需在读图时做 `ImageOps.exif_transpose` 转正，避免标注框和实际画面对不上。

## 6. `training/classes.yaml` 设计

这是**训练侧（类别定义）与运行侧（`core/recognizer.py`/`core/nutrition.py`）共用的唯一真源**，避免出现"代码里类别映射写一份、训练配置里又写一份"导致后期不同步的问题。

```yaml
version: 1
classes:
  - id: 0
    name: tomato          # 模型类名，即 data.yaml 中 names[i]，训练/推理返回的类别名
    zh: 西红柿             # 中文展示名
    ingredient: 西红柿      # 对应 data/ingredients.json 的 name 或 aliases，用于查营养
    unit: piece            # piece=按个计数×单重 | bulk=整份取默认重量（不易计数的蔬菜/肉类）
    default_weight_g: 150  # 参考单重/份重，用户可在页面上修改
    sources:                # 各数据源里对应的原始类名，供 prepare_dataset.py 做类别映射
      lvis: [tomato]
      zenodo: [Tomato]
      openimages: [Tomato]
      custom: [tomato]
  - id: 1
    name: egg
    zh: 鸡蛋
    ingredient: 鸡蛋
    unit: piece
    default_weight_g: 50
    sources:
      openimages: ["Egg (Food)"]
      custom: [egg]
  # ... 其余 31 类同理，按 §1 表格逐一列出
```

**已知需要修正的映射**（探索 `data/ingredients.json` 时发现）：
- `chicken`（鸡肉）：`ingredients.json` 中规范名是"鸡"，没有"鸡肉"这个别名，需要在 `data/ingredients.json` 对应条目的 `aliases` 数组里补上 `"鸡肉"`。
- `fish`（鱼）：`ingredients.json` 中只有"草鱼/鲈鱼/鲤鱼/带鱼"等具体鱼种，没有笼统的"鱼"。两个方案二选一：(a) `ingredient` 直接指向"草鱼"作为默认映射；(b) 给"草鱼"条目的 `aliases` 补上 `"鱼"`。建议用方案 (b)，因为检测模型本身也很难细分鱼的品种，笼统识别为"鱼"更符合实际能力。

## 7. `prepare_dataset.py` 数据构建流程

1. **校验类别定义**：`food_classes.load_classes()` 读取 `classes.yaml`，`validate()` 检查每个 `ingredient` 字段能否在 `ingredients.json` 索引中命中，命令 `python training/prepare_dataset.py --check-classes` 应输出 `missing: []`。
2. **各源适配器转换**：`training/sources/{lvis,zenodo,mendeley,openimages,custom}.py` 各自实现 `iter_samples(raw_dir) -> (img_path, [(src_cls, x1,y1,x2,y2), ...])`，统一产出绝对像素坐标的框。
3. **类别映射**：用 `classes.yaml` 里每类的 `sources` 字段建立"数据源原始类名 → 本项目 33 类 id"的映射表；映射不到的框直接丢弃（不是丢弃整张图，图里其余有效框仍保留）。
4. **去重**：文件内容 md5 去重 + 简单的 PIL 平均哈希去重（不同数据源之间可能收录了同一张网图）。
5. **划分数据集**：按每张图的主类别做分层抽样，`train:val:test = 8:1:1`；自采数据（`custom`）默认不进入训练集，整体作为独立测试集 `training/datasets/fridge_test`，另外划出 50% 用于微调实验（见 02 §6 E5）。
6. **产出物**：
   - `training/datasets/yolo/{images,labels}/{train,val,test}/`（标准 YOLO 目录结构）
   - `training/data.yaml`（`path`/`train`/`val`/`test`/`names`）
   - `training/data_fridge.yaml`（单独指向自采测试集）
   - `training/reports/dataset/<输出目录名>/class_distribution.png`（各类别在 train/val/test 中的框数分布图，对数刻度，matplotlib 生成）
   - `<输出目录>/summary.json`（每类每 split 的框数、图数、各来源占比），副本在 `training/reports/dataset/<输出目录名>/summary.json`

**验收标准**：`summary.json` 中每个类别在 train 集的框数不少于 200（低于此数的类别考虑合并近似类别或加大自采比重）；随机抽取 20 张标注结果，用简单脚本画框肉眼核对框和标签是否对齐。
